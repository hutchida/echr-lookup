# Task I3: Stats (corpus, ingestion, cost, eval)

- **Model:** `github-copilot/claude-sonnet-5.5` (opencode)
- **Database / ports:** `echr_i3`, API 8003, web 3103 (`docs/interfaces.md` §10)
- **Runs in parallel with:** I1 Ask + case viewer, I2 Lab (disjoint paths)
- **Common rules:** `docs/orchestration/tasks/gate2-common.md` (binding; read it first)

## Goal
`/stats` is the system's dashboard: what is in the corpus, how the last ingestion went, what the app has cost, and how well retrieval and answers score in the eval. It's the screen that turns "trust me" into numbers.

## Owned paths
- `apps/web/app/stats/**` (route-local components in `apps/web/app/stats/_components/`)
- `docs/learn/I3.md`, `docs/learn/img/I3-*.png`, `packages/capture/specs/I3-*.json`

## Must not touch
Everything else: `layout.tsx` and `apps/web/components/**` are I1's (don't import from them; the nav link to `/stats` already exists), `apps/web/lib/api.ts`, the contract, `py/**`.

## Build (data from `getStats`, `getIngestRuns`, `getCosts`, `getEvalRuns`, `getEvalRun`)
- **Corpus** (`stats-counts`): totals (documents, paragraphs, chunks per strategy) and counts by doc type, outcome, chamber, article and year. Simple, readable bars or tables (plain HTML/CSS; no chart library). Show `data_source` (snapshot/full).
- **Ingestion** (`stats-ingest`): the last run prominently, with per-stage timings (e.g. a horizontal bar per stage with seconds) and counts (seen / loaded / skipped / failed); older runs in a compact table.
- **Cost** (`stats-costs`): running app cost from `cost_log` (total, by model, by purpose, and request count if available). Add one line explaining it covers runtime calls (embedding, answers, citation checks, eval judge) since the last DB reset; local models cost $0.
- **Eval** (`stats-eval`): the results table across chunking × search mode (recall@k, MRR, and where present faithfulness, citation accuracy, neutrality, stat accuracy), matching `docs/eval-results.md` for the same runs. Mark the best value per metric. One-line definition of each metric (hover or footnote). Optional: `/stats/eval/[id]` with one run's per-question results.
- Run independent API calls in parallel (`Promise.all`); render each section's error state independently, so one failing endpoint doesn't blank the page.

## Tests
Pure functions with vitest on `CorpusStats.json`, `IngestRunList.json`, `CostSummary.json`, `EvalRunList.json`, `EvalRun.json`: bar widths/percentages, stage-duration formatting, money formatting (sub-cent values), building the chunking × mode eval table and picking the best per metric, missing/null metric handling.

- `/stats` fully rendered **< 2 s**; report the number.
- The numbers on the page match the API (`curl localhost:8003/stats`, `/costs`, `/eval-runs`): spot-check 3 in the PR.
- One endpoint failing still renders the other sections.
- Capture spec + screenshot `I3-stats` (full page).
- Learning doc `docs/learn/I3.md`: what each eval metric measures in plain English (recall@k, MRR, faithfulness, citation accuracy, neutrality, stat accuracy) with an example from this corpus, why cost logging per call matters, and how to read the ingestion timings.
