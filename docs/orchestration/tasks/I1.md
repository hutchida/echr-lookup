- **Model:** `github-copilot/claude-sonnet-5.5` (opencode)
- **Database / ports:** `echr_i1`, API 8001, web 3101 (`docs/interfaces.md` §10)
- **Runs in parallel with:** I2 Lab, I3 Stats (disjoint paths)

## Goal
The two screens the demo opens on: `/ask`, where a question becomes a cited, verified answer (or a stats answer with its SQL), and `/case/<id>`, where a clicked citation opens the exact paragraph highlighted. You also own the shared layout and home page. This UI is how a viewer learns to **trust or doubt** an answer, so make the evidence (citations, verification, route, cost) visible, not hidden.

## Build
### `/ask`
- A labelled question box (`ask-input`) and submit button (`ask-submit`), plus the three demo questions as one-click examples.
- **Recommended shape:** the form submits GET to `/ask?q=…`; the page renders the shell at once and streams the answer in a `<Suspense>` boundary (server component calling `ask()` from `@/lib/api`) with a clear "Thinking… (usually 5–10 s)" state. That keeps the page load < 2 s, makes answers linkable for the demo, and needs no client fetch. A Server Action is acceptable if you have a reason; say why in the PR.
- **RAG answers (`route: "rag"`):** the answer text with **inline citation chips** (`citation`) at the claims they support. Each chip shows the case and paragraph (e.g. "Soering v UK §88") and links to `Citation.link_target` (`/case/<doc_id>#p<ref>`). Each claim shows its verification badge (`claim-status`: supported / unsupported / unverified, with the `reason` on hover or expand); not by colour alone. A short "Sources" list underneath.
- **Stats answers (`route: "stats"`):** the count, the top reasons, the SQL used in a readable code block (`stats-sql`), and the matched cases listed with links to `/case/<id>`.
- **Refused / no-answer** (`Answer.refused.json`): a calm, explicit message.
- **Always visible:** the route taken (`answer-route`: "RAG: retrieved + cited" vs "Stats: SQL over metadata"), latency, and **the cost of this answer** (`answer-cost`: total plus the per-step breakdown from `Answer`'s step costs).
- Keep it neutral: no editorial framing around the answer.

### `/case/[id]`
- Header: case name, date, doc type, chamber, articles, outcome, importance, ECLI, and a link to the HUDOC source.
- Every paragraph in document order, grouped under its section (Procedure / The Facts / The Law / Operative provisions…), each with `data-testid="case-paragraph"` and `id="p<ref>"` (`ref` = the part of the paragraph ID after `§`), showing its number.
- **Highlight the target:** CSS `:target` (Tailwind `target:` variant) so it works without JS, plus a tiny client component that scrolls to it, sets `data-highlighted="true"` on it and follows hash changes.
- Unknown id → a readable 404 state (the API returns `ApiError`), not a crash.

### Shared
- Layout/nav as in §9; you may restyle it. Home page: one sentence on what this is, links to the three demo questions, Lab and Stats, and the existing API status card.
- Put components used by both your pages in `apps/web/components/`.

## Tests
- Pure functions for display logic (e.g. citation ref → anchor, splitting answer text into claim segments with chips, cost formatting, grouping paragraphs by section) with vitest on `Answer.json`, `Answer.stats.json`, `Answer.refused.json` and `CaseDetail.json`.
- Optionally `renderToString` a component to assert the testids and anchors exist.

## Acceptance (in addition to the common rules)
Run against your API on `echr_i1` (warm):
- `/ask` (empty) and `/case/001-57619` load < 2 s each; report the numbers.
- Demo Q1 and Q2 on `/ask?q=…` with **live** `LLM_MODE` (your $1 allowance): answer with citation chips and badges < 15 s; clicking a chip opens `/case/…#p…` with that paragraph highlighted. Q3 shows the stats route with SQL and cases. Develop with `LLM_MODE=fake`; use live only for these final checks (≤ ~10 asks).
- An API error (stop the API, or ask for `/case/001-99999`) shows a readable error.
- Capture specs + screenshots: `I1-ask-q1` (answer with chips), `I1-ask-stats` (Q3), `I1-case-highlight` (highlighted paragraph).
- Learning doc `docs/learn/I1.md`: what a citation chip and a verification badge mean (and what "unsupported" tells you), why the router sends counting questions to SQL, and how to check an answer against the paragraph yourself.
