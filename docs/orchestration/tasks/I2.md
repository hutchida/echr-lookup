# Task I2: Lab (the retrieval teaching screen)

- **Model:** `github-copilot/claude-sonnet-5.5` (opencode)
- **Database / ports:** `echr_i2`, API 8002, web 3102 (`docs/interfaces.md` §10)
- **Runs in parallel with:** I1 Ask + case viewer, I3 Stats (disjoint paths)
- **Common rules:** `docs/orchestration/tasks/gate2-common.md` (binding; read it first)

## Goal
`/lab` shows **how retrieval works** by running one query through each search method side by side: BM25 (keyword), vector (meaning), fused (hybrid via Reciprocal Rank Fusion, RRF) and reranked (a cross-encoder re-scoring the fused list). This is the main teaching screen: a viewer should see, for the demo question, that different methods find different paragraphs and why the final list is better.

## Owned paths
- `apps/web/app/lab/**` (route-local components in `apps/web/app/lab/_components/`)
- `docs/learn/I2.md`, `docs/learn/img/I2-*.png`, `packages/capture/specs/I2-*.json`

## Must not touch
Everything else: `layout.tsx` and `apps/web/components/**` are I1's (don't import from them; the nav link to `/lab` already exists), `apps/web/lib/api.ts`, the contract, `py/**`.

## Build
- **Controls** (a GET form, so `/lab?q=…&chunking=recursive&k=10` is shareable and the demo can open it directly): query (`lab-query`, default the demo question "Does the Convention stop the UK deporting criminals?"), chunking strategy (`fixed` / `recursive` / `by_section`, default `recursive`), k (default 10). Optional: article / doc-type filters if `SearchRequest.filters` makes it cheap.
- **Four columns** (`lab-column-bm25`, `lab-column-vector`, `lab-column-fused`, `lab-column-reranked`), each that method's own top-k: rank, score (labelled with what the number is: BM25 score, cosine similarity, RRF score, cross-encoder score), case name, paragraph IDs (link to `/case/<doc_id>#p<ref>`), a short snippet, and the chunking strategy.
- **"What you're seeing"**: one plain-English line per column (e.g. BM25 "matches the exact words; great for names like *Soering*, blind to synonyms"), plus a short intro above the columns.
- **Make movement visible:** mark the same chunk across columns (e.g. a shared colour key or rank badge by chunk id) and show rank change from fused → reranked (↑3 / ↓2 / new). This is the point of the screen.
- **Timings:** each column's latency (`SearchResult.timings_ms` and/or `ApiResult.ms`).
- **How to get the data:** decide after reading `SearchHit` / `SearchResult` in `packages/contract/src/search.ts` and `docs/learn/S3.md`. Most likely: four parallel `search()` calls (`bm25`, `vector`, `hybrid`, `hybrid_rerank`) with `Promise.all`, because a single fused call only reports BM25/vector ranks for chunks in its own candidate pool. Say in the PR which you chose and why.
- If reranking is disabled on the API, the reranked column says so instead of failing.

## Tests
Pure functions with vitest on `SearchResult.json` (and small variants built from it): score labels, rank-change computation between two hit lists, chunk → colour/badge assignment, query-param parsing with defaults and invalid values.

## Acceptance (in addition to the common rules)
Against your API on `echr_i2` (warm, real embedder, `RERANK_ENABLED=1`):
- `/lab` (default query) and `/lab?q=<demo Q1>&chunking=recursive` fully rendered **< 2 s**; report the numbers. If the reranked column alone pushes it past 2 s, stream it in its own `<Suspense>` so the other three render < 2 s, and report both times.
- Switching chunking strategy changes the hits (show one example in the PR).
- An API error renders readably.
- Capture spec + screenshot `I2-lab-q1` (all four columns for the demo question).
- Learning doc `docs/learn/I2.md`: the most important learning doc of Gate 2. Explain BM25, embeddings/vector search, RRF and cross-encoder reranking, and chunking strategies, each with an example *from this screen* (e.g. a paragraph that BM25 ranks high and vector misses, or vice versa). Try-its are URLs into `/lab` with what to look for.
