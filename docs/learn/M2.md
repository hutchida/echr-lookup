# M2: comparing "Claude + MCP tools" with `/ask`

## 1. What this is, in plain English

echr-lookup already answers questions itself: the **`/ask` pipeline** looks up paragraphs, one model writes a cited answer, and a second model checks each claim against the paragraph it cites. The MCP slice offers a different arrangement. An **MCP server** (MCP = Model Context Protocol, a standard way for an AI app to call a program's *tools*) exposes six tools (`search_case_law`, `get_paragraphs`, `get_case`, `count_cases`, `corpus_info`, `check_quote`), and the AI app's own model (the *host*, here Claude Sonnet 5.5) decides which to call, reads what comes back and writes the answer. echr-lookup only supplies evidence.

M2 is the experiment that tells us which arrangement answers better. It is a **harness** (a test rig, not part of the app) that asks the same questions both ways, scores every answer with the same measurements, and writes a side-by-side report in `docs/mcp-comparison.md`. It does not decide anything; the decision memo comes after Dan has read the answers.

Two terms you will meet: a **tool loop** is the back-and-forth where the model asks for a tool, the harness runs it and returns the result, and the model asks again or answers; **prompt caching** is the Anthropic API feature that bills text it has already seen in this conversation (the instructions, the tool list, earlier tool results) at a fraction of the normal input price.

## 2. Why it matters

Take the owner-review question *"Does the Convention stop the UK deporting criminals?"*. `/ask` retrieves one batch of paragraphs and writes one answer. Claude with tools can search for Article 3, search again for Article 8, open the paragraphs around a hit with `get_paragraphs`, and look for a case where deportation was allowed. That may give a richer answer, or it may cite a paragraph it never opened, quote something that is not in the paragraph, or cost several times as much. Only measuring tells us, and only measuring the *same* things on both sides makes the numbers comparable:

- Did the answer have the right *shape* (the owner-review checks: a qualified opening, several cases cited, the corpus described as a UK sample)?
- Did the cited paragraphs support each claim (the existing judge, unchanged)?
- Were quotes word for word (`check_quote`)?
- Was the right paragraph even in front of the model (**agentic recall**: of the paragraphs a human marked as the right evidence, how many appeared in any tool result)?
- What did it cost, in tokens, dollars and seconds?

## 3. How it works here

Everything is in `py/rag/eval/agentic/`.

```
python -m rag.eval.agentic ──► runner.py: one job per (system, question, repeat)
                                   │
        ┌──────────────────────────┴──────────────────────────┐
   system "mcp"                                          system "ask"
   host.py  Host.ask()                                   ask_side.py run_ask()
     │  Messages API (client from rag.config)              rag.answer.answer(conn, {"question"})
     │  system = server instructions, tools = list_tools()      (records the paragraphs it put
     ▼                                                           in its generation context)
   MCP session over stdio ──► `python -m echr_mcp` (real)
                              or fake_server.py (contract fixtures)
        └──────────────────────────┬──────────────────────────┘
   text.py: split the answer into claims, resolve citations, find quotes
   checks.py + quotes.py: recall, quote rate, shape checks (no model)
   judging.py: judge_support (unchanged) + one call for the prose checks
                                   ▼
        data/eval/agentic/results.jsonl  ──►  report.py  ──►  docs/mcp-comparison.md
```

- **`host.py`** starts the server once (loading the models takes 10–30 s) and keeps the session for the whole run. `Host.ask` calls the model with the tools, runs each `tool_use` through the session, returns the JSON text as a `tool_result`, and stops at the final answer. After 8 tool calls it sets `tool_choice: none` so the model must answer from what it has. Every model call is written to `cost_log` with `purpose = "agentic"`.
- **`fake_server.py` / `fake_client.py`** are the offline stand-ins: a real MCP server over stdio that answers every call with the matching contract fixture, and a scripted fake of the Anthropic client. CI runs the whole loop with both.
- **`text.py`** turns the host's free text into claims. A citation is either the tool's `cite` string `[Chahal v. the United Kingdom, Judgment, §79]` (mapped to a paragraph id through what the tools actually returned) or a bare id `001-58004§79`. Markers it cannot map are listed as unresolved, not guessed.
- **`checks.py`** holds the deterministic metrics; **`quotes.py`** is `check_quote` as the interface spec defines it (a live run uses the server's own function once it is merged).
- **`--max-cost`** is a hard cap shared by every paid call (answers and judging). The harness estimates each call *before* sending it and stops if it would cross the cap; everything it did not run is written to the results file as `skipped_budget` and printed, never silently dropped.

pnpm run eval:agentic --fake --set owner-review --repeats 1 --max-cost 1 --only or-09 --systems mcp,ask

Expected: two progress lines, `mcp or-09 x1 ok` and `ask or-09 x1 ok`, then `spent $0.0xx of $1.00; 2 rows written` (the fake model searches, reads paragraph §79 of Chahal, answers). ## 5. Limits / what can go wrong

- **Small, noisy sample.** 10 owner-review questions × 3 samples and 30 retrieval questions on a 98-document corpus: differences of a few points are noise. A model's answers vary between samples, which is why the owner-review set is repeated.
- **The judge is a model, and a relative.** `judge_support` runs on Sonnet 5.5, which is also the host and `/ask`'s writer. It sees only the paragraph text and the claim, but it is not independent of the systems it grades. The claim split is mine, not the model's: the parser is simple (sentences and bullets, citations mapped by id or `cite` string), so a citation written in an unusual form is reported as unresolved rather than guessed.
- **Uncited claims are not judged**, they are counted. A system that cites rarely can look accurate on the claims it does cite; read the "claims with no citation" row next to the accuracy rows.
- **Quotes** are only the double-quoted passages of four or more words; paraphrase, single quotes and short quoted phrases are not checked.
- **Recall is not quality.** A model can be shown the gold paragraph and ignore it, or answer well from a different paragraph. Recall only says the evidence was in front of it.
- **Costs differ in kind.** The tool loop's cost depends on what the model decides to do (the cap of 8 calls bounds it); `/ask`'s is nearly fixed. `cost_log` books cache writes at the plain input price, so it runs a little below the per-question figures in the report.
- **The owner-review set is a draft** (`status: draft`), and its checks are hints, not truth: a correct answer can fail one (for instance `mentions`) and a weak one can pass. `no_bare_yes_no` fails an answer whose first sentence starts with Yes or No and carries no qualifier ("No, not as a general rule" passes, "No." fails): a word-list rule that can be wrong at the edges.
