# M1: the MCP server (Claude and ChatGPT reach our case law through tools)

Box 6 on the map in [`00-overview.md`](00-overview.md) gets a second front door. Setup for Claude Desktop, Claude Code and the Inspector: [`../mcp-setup.md`](../mcp-setup.md). Tool and result shapes: [`../interfaces-mcp.md`](../interfaces-mcp.md).

## 1. What this is, in plain English

**MCP** (Model Context Protocol) is an open standard for letting an AI app use *tools* that live in another program. The AI app is the **host** (Claude Desktop, Claude Code, ChatGPT). Our program is an **MCP server**. When you ask Claude a question, the model can decide to call one of our tools, for example "search the case law for deportation and Article 3", get a structured answer back, read it, and write its reply. The server never writes prose and never calls a language model. It only supplies **evidence**: paragraphs with a ready-made citation, exact counts with the SQL behind them, and a way to check a quote.

There are six tools, all read-only. `search_case_law` finds paragraphs (keyword + meaning search, reranked). `get_paragraphs` and `get_case` read around a hit or a whole case. `count_cases` answers "how many" by filling a fixed, validated template (the model never writes SQL). `corpus_info` says what the corpus holds and lacks. `check_quote` says whether a quote really appears, word for word, in a paragraph.

A server talks to its host over a **transport**. **stdio** means the host starts our program as a child process and the two exchange JSON messages through standard input and output (nothing else may be printed there). **Streamable HTTP** means the server listens on a web address (`http://127.0.0.1:8101/mcp`) and clients send it requests. Same tools either way. Each tool also advertises a **JSON Schema** for its arguments and its result, taken unchanged from our contract (`packages/contract`), so the host knows exactly what to send and what it will get.

## 2. Why it matters

The `/ask` pipeline is a *closed* box: our own code retrieves, a model we picked writes, a verifier checks. MCP opens it the other way: the host's own, probably stronger, model does the reading and writing, and we supply the evidence. That makes a fair comparison possible (M2 measures "Claude + our tools" against `/ask`), and it means anyone with Claude Desktop can use the corpus without our web app.

A concrete case. Ask Claude Desktop *"How many Grand Chamber judgments are in the corpus, and how many found a violation?"* The instructions the server sends say "for any 'how many' question call `count_cases`; never count search results". The tool returns `count 9, scope_total 10`, the sentence *"The indexed corpus has 10 Grand Chamber judgments; 9 of them found at least one violation."*, the definitions ("found a violation" means outcomes `violation` and `mixed`), the exact SQL, and the nine cases. Claude can report 9 and 10 and show its working. Without the tool it would have counted whatever a search returned and been confidently wrong. Likewise `check_quote` stops a polished-sounding quotation that is slightly reworded from reaching the answer as if it were verbatim.

## 3. How it works here

```
Claude Desktop / Claude Code / scripts/mcp_call.py
     │  stdio (child process)        or      streamable HTTP  127.0.0.1:<port>/mcp
     ▼
py/echr_mcp/__main__.py   --transport stdio|http   (MCP_PORT, default 8100)
     │
py/echr_mcp/server.py     low-level SDK Server: instructions, six tools with the contract's
     │                    input/output schemas, read-only annotations; validate → run → check → log
py/echr_mcp/tools.py      six plain functions  tool(conn, args) -> contract dict
     │                         │ calls (no HTTP, no LLM)
     │                    rag.search.search · rag.answer.citations/stats/context · api.queries
py/echr_mcp/common.py     display_case_name, cite, corpus block, plain labels, size limit
py/echr_mcp/toollog.py    one row per call → table tool_log   (infra/migrations/mcp_0001_tool_log.sql)
     ▼
ParadeDB (BM25 + pgvector)
```

- **One call:** the server checks the arguments against the contract schema (a bad argument is an *error result* with one plain sentence, so the model can fix it and retry), runs the tool in a worker thread, checks the result against the contract again (a bug becomes an error, never a malformed answer), sends it as `structuredContent` **and** as one text block holding the same JSON (older clients read the text), and writes a `tool_log` row. Logging never fails a call.
- **Models load once**, at startup, then warm up with one dummy embed and rerank, so the first real search is not a cold start (about 7 s at startup, about 1 s per search afterwards).
- **`search_case_law`** runs the same setup `/ask` uses (hybrid + rerank, recursive chunks) but over-fetches 30 chunks, then picks, per chunk, the one *paragraph* whose best sentence matches the query. Hits are distinct paragraphs, best first, each with a verbatim `quote` (whole sentences; a `…` marks a cut inside one) and a `cite` such as `[Chahal v. the United Kingdom, Judgment, §79]`.
- **`count_cases`** reuses `rag.answer.stats` functions (`sanitize_params`, `build_query`, `execute_readonly`, …) without editing them; a test proves it returns the same `count`, `scope_total` and `rows` as `/ask`'s stats path for the same parameters.
- **Size:** every result is at most 25,000 bytes. `get_paragraphs` cuts neighbours' text first, then requested text, at a sentence end, ends it with `…` and sets `truncated: true`.
- **`check_quote`** is deterministic. It normalises both texts (Unicode NFKC, curly → straight quotes, `–`/`—`/`‑` → `-`, runs of whitespace → one space), splits the quote at `…` / `...` / `[...]` into segments, and says `verbatim` only if every segment occurs in the paragraph, in order. If not, `closest_match` is the 1–3 consecutive sentences with the highest `difflib` similarity, copied from the paragraph. Quotation marks you add around the quote are *not* ignored.
- **Corpus note:** every result carries `corpus` (documents, `data_source`, scope, and in snapshot mode "small sample") so the host can say *"not found in this sample"* rather than *"the Court never decided that"*.

## 4. Try it

Start from the repo root with the database up (`pnpm db:up`). The helper script `scripts/mcp_call.py` is a tiny MCP client; without `--url` it starts the stdio server itself (about 7 s, the models loading).

**1. List the tools**

```bash
cd py && uv run python ../scripts/mcp_call.py list
```
Expected: six lines, `search_case_law`, `get_paragraphs`, `get_case`, `count_cases`, `corpus_info`, `check_quote`, each with its first sentence. *Proves:* the server starts over stdio and advertises exactly six tools. (To see the schemas and read-only annotations too: `npx @modelcontextprotocol/inspector --cli --method tools/list -- uv run --frozen --directory py --group ml python -m echr_mcp --transport stdio`.)

**2. One search**

```bash
cd py && uv run python ../scripts/mcp_call.py call search_case_law \
  '{"query":"deport a person to a country where they face a real risk of torture, national security","article":"3","limit":3}'
```
Expected: `"filters": "Article 3"` and three hits ranked 1–3, all Othman (Abu Qatada): `[Othman (Abu Qatada) v. the United Kingdom, Legal summary, §u3]`, `…, Judgment, §25]`, `…, Judgment, §185]`, each with a `quote`; about 1 s on stderr (`-- 1.06 s`). *Proves:* hybrid search with a filter works and returns citable paragraphs, not chunks. Note the first hit is a **Legal summary**, the Court's digest, which is why the server's instructions tell the host to say so when citing one.

**3. One count**

```bash
cd py && uv run python ../scripts/mcp_call.py call count_cases \
  '{"doc_types":["judgment"],"chambers":["Grand Chamber"],"outcomes":["violation","mixed"],"count_of":"total_and_subset"}'
```
Expected: `"count": 9`, `"scope_total": 10`, `"answer": "The indexed corpus has 10 Grand Chamber judgments; 9 of them found at least one violation."`, three `definitions`, the exact `sql`, two `rows`, and nine `matching_cases`. *Proves:* a "how many" question is answered by validated SQL, with the working shown, never by counting search results.

**4. Check a quote**

```bash
cd py && uv run python ../scripts/mcp_call.py call check_quote \
  '{"paragraph_id":"001-58004§79","quote":"the Convention prohibits in absolute terms torture … irrespective of the victim’s conduct"}'
```
Expected: `"verbatim": true`, `"similarity": 1.0`, `closest_match` the full sentence from Chahal §79 (the curly apostrophe matched the paragraph's straight one, and `…` marked the omission). Now reword it: `"quote":"Article 3 forbids ill-treatment absolutely, whatever the victim has done"` → `"verbatim": false`, `"similarity": 0.3563`, and the same sentence as `closest_match`. *Proves:* the check is strict about words and lenient only about punctuation, so a paraphrase can't pass as a quotation.

**5. The same over HTTP**

```bash
MCP_PORT=8101 pnpm run mcp:http          # terminal 1; leave running (Ctrl-C to stop)
cd py && uv run python ../scripts/mcp_call.py --url http://127.0.0.1:8101/mcp call corpus_info   # terminal 2
```
Expected: terminal 1 ends with `Uvicorn running on http://127.0.0.1:8101`; terminal 2 prints `"totals": {"documents": 98, "paragraphs": 9430}`, counts by document type, outcome and Article, the year range 1950–2025, and a `missing` list (Commission reports, scanned decisions…). *Proves:* the streamable-HTTP transport serves the same tools, bound to `127.0.0.1` only.

**6. Read the call log**

```bash
docker compose exec -T db psql -U echr -d echr_m1 -c \
  "select id, tool, ok, round(latency_ms) as ms, result_bytes, transport from tool_log order by id desc limit 5"
```
Expected: one row per call you made, newest first, e.g. `check_quote | t | 18 | 534 | http`, a `get_case | f` row (an error) if you asked for an unknown case, and `stdio` / `http` in the last column. (Use your own database name in place of `echr_m1`.) *Proves:* every call is logged with its arguments (`args` column), outcome, latency and size, the data that answers "what did Claude actually ask for?". The table is not in `rag.index`'s reset list, so `reset()` leaves it alone.

## 5. Limits / what can go wrong

- **Startup time.** About 7 s with the real models. Claude Desktop waits for this; a slow disk or a cold model cache can make the first start look hung. Check `~/Library/Logs/Claude/mcp-server-echr-lookup.log` for `ready (transport=stdio)`.
- **Not connected, not public.** The HTTP server listens on `127.0.0.1` and rejects other `Host` headers. It has **no authentication**. ChatGPT and claude.ai need a public HTTPS URL and an auth scheme, which waits for M3's hosting decision ([`../mcp-setup.md`](../mcp-setup.md), last section).
- **Same limits as `/ask`'s retrieval.** The snapshot is 98 documents; "not found" means *not in the sample*. A tool call can still return plausible-looking weak hits: the reranker's scores are not shown. Counting depends on metadata (outcome, grounds) and on the "deportation" definition (an article test plus at least two paragraphs mentioning deport/expel/…); the `definitions` field says so, and the host should repeat it.
- **Trimming loses text.** `get_paragraphs` may cut long paragraphs to stay under 25 KB (flagged `truncated: true`); ask for one paragraph alone to get its full text. In the extreme (ten requested paragraphs with neighbours, each very long) the farthest neighbours are dropped.
- **The host can ignore the rules.** The server's `instructions` ask for citations, a leading answer and neutrality, but a host model may not obey. That is exactly what M2's comparison measures.
- **`check_quote` is only as good as the text.** Differences beyond whitespace, quotes, dashes and `…` (a dropped comma, a changed word) make it `false`. Stripping quotation marks the model adds around a quote is deliberately *not* done.
- **Models in one process.** Searches are serialised behind a lock; two clients searching at once queue (about 1 s each). Fine for one person, not a hosting design.
- **SDK v2 is new.** The server uses the SDK's low-level `Server` so the contract schemas go out untouched, which means the SDK does not check arguments for us; `server.py` does, and a test calls every tool through a real client to keep that honest.
