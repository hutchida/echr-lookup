# F3: is the Claude + tools vs `/ask` comparison fair?

## 1. What this is, in plain English

The M2 comparison (`docs/learn/M2.md`) found that Claude with the MCP tools beat `/ask` at *finding* the right paragraphs (60% against 23% "agentic recall") but wrote many sentences with no citation and quoted loosely. Before anyone builds a decision on those numbers, F3 asks whether the comparison itself was fair. This is **part 1**: four checks that cost nothing because they reuse what M2 already recorded. **Part 2** (a paid re-run of Claude + tools against F1's improved server) was prepared but **not run**: the Anthropic key is at its usage limit until 2026-12-01. What is ready, and the commands to run it later, are in section 4b.

Terms used below. **Recall@k**: take the search's ranked list, keep the first k results, and ask what share of the "gold" paragraphs (the ones a human marked as the right evidence) are in them. A search result is a *chunk* that can cover several paragraphs; recall counts the paragraphs. **Agentic recall**: the same share, but over every paragraph a model was actually shown while answering, not a ranked list. **Answer key**: the list of gold paragraphs per question. The original key came with the question set (about 2 gold paragraphs per question); **qrels-v2** is a second, wider key written by an AI judge (about 10 per question; PR #28, `docs/eval-judging.md`). A **quote check** asks whether a double-quoted passage in an answer appears word for word in a paragraph.

## 2. Why it matters

Take the claim "`/ask` finds only 23% of the right paragraphs". It could mean `/ask` is looking in too few places (searching *more* would fix it), or looking badly (a smarter way of searching is needed). The check: run `/ask`'s own search at k = 40 and see. It reaches 42% of the original key (63 paragraphs), still far below Claude's 60% from about 21 paragraphs. So Claude searched smarter, not just more. On the wider qrels-v2 key the same list reaches 65%, because the gold set is five times larger. The conclusion depends on the key, and now we can say so with numbers.

The second example is question or-09 ("can a person's own conduct, such as involvement in terrorism, justify deporting them…?"). Both systems "failed" it. Neither gave a wrong answer: all six say No, Article 3 is absolute. The checks were too narrow (one named paragraph, when five say the same sentence) and a quote rule that counts an uncited quote as not verbatim.

## 3. How it works here

Code: `py/rag/eval/agentic/fairness.py` (tests: `test_fairness.py`). Data in: `data/eval/agentic/results.jsonl` (M2, never changed), `data/eval/judgments/qrels-v2.jsonl`. Data out: `data/eval/agentic/fairness-hits.jsonl` (the saved search hit lists, so recall can be recomputed without a database) and `fairness.json` (the numbers). The write-up is the section "Fairness checks, free part" of `docs/mcp-comparison.md`.

```
questions.jsonl (59 with gold) ─► search(hybrid_rerank, recursive, k=40) ─► fairness-hits.jsonl
                                                                              │ recall@5/10/12/20/40,
 qrels-v2.jsonl ──────────────────────────────────────────────────────────────┤ old key and v2
 results.jsonl (fetched_paragraph_ids, quotes) ──► rescore / quote audit ─────┘
```

One small change to the harness itself: each recorded tool answer now also gets `in_shown`, `in_shown_nocase` per quote and `quote_rate_shown` per answer (is the text in *any* paragraph the model was shown?), next to the unchanged headline `quote_rate`. The M2 rows pre-date it; the audit below recomputes it for them.

## 5. Limits / what can go wrong

- **qrels-v2 is one AI judge's opinion**, from a Claude model like the systems under test, and five times wider than the old key. Treat the v2 columns as a second view, not the truth. Owner-review questions have no v2 key at all.
- **Different kinds of number.** Recall@k is a ranked list cut at k hits; agentic recall is "paragraphs a model was shown". The paragraph-cut rows put them on equal footing in amount of text, not in how they were chosen. Claude averaged four searches; the search rows have one query.
- **Recall is not answer quality.** A model can be shown the right paragraph and ignore it.
- **The quote audit is about text, not meaning.** "In some shown paragraph" can be a different case's paragraph that happens to share the words; the audit does not check that the quote supports the claim, which is the judge's job.
- **Sample size.** 30 subset questions and 10 × 3 owner-review answers: a few points are noise.
- **The re-run is not done.** Until the key works, the "after F1" column is `not run`; nothing in it is estimated. The harness changes are tested offline only, against F1's fixtures, not against a real answer.
- **Rules not changed.** The headline quote rule and the owner-review checks are left as M2 defined them so the numbers stay comparable; the audit sits beside them. The answer key `owner-review.jsonl` is read-only for F3.
